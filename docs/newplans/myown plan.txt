### 1.2 Current Design Tokens in Use

**`theme/Color.kt`** — Already updated to mockup values. Contains:
- `BrandColors` object with 30+ named constants
- `HistoryCardAccents` list of 5 gradient pairs
- All values match the HTML mockup CSS variables (verified hex-by-hex)

**`theme/Type.kt`** — References `R.font.space_grotesk` and `R.font.dm_sans` (both exist as variable TTFs in `res/font/`). Defines 10 type roles via `AppType` object. Maps to Material3 `Typography` via `AppType.material`.

**⚠️ CRITICAL BUG in Type.kt:** Every single property uses `@Composable get()`:
```kotlin
private val SpaceGrotesk: FontFamily
    @Composable get() = FontFamily(
        Font(R.font.space_grotesk, FontWeight.Medium),
        Font(R.font.space_grotesk, FontWeight.SemiBold),
        Font(R.font.space_grotesk, FontWeight.Bold)
    )
```
This creates a **new `FontFamily` instance on every recomposition**. `FontFamily` construction involves font resource lookups. On a screen with 20+ `Text` composables, this runs dozens of times per frame during animation. This must be a top-level `val` or use `remember`.

**`theme/Shape.kt`** — 4 shapes: `small` (8dp), `medium` (12dp), `large` (20dp), `pill` (999dp). Plus `AppShape.material` mapping to M3 `Shapes`.

**`tokens/Spacing.kt`** — 8pt grid: `xs`=4, `sm`=8, `smMd`=12, `md`=16, `lg`=24, `xl`=32, `xxl`=48, `xxxl`=64. Plus semantic aliases (`cardPadding`, `screenPadding`, etc.).

**`tokens/Motion.kt`** — Durations (150/200/300/500/3200ms), 4 easings (Standard/Decelerate/Accelerate/Emphasized), 3 spring specs (bouncy/snappy/gentle).

**`tokens/Elevation.kt`** — 5 levels: none(0), card(2dp), cardHover(6dp), modal(12dp), popover(8dp).

**`theme/Theme.kt`** — Dark-only (`ForceDark = true`). Maps `BrandColors` → `darkColorScheme`. Edge-to-edge via `SideEffect`. Light scheme exists but is a generic white/black placeholder.

#### SplashScreen — `ui/splash/SplashScreen.kt`

**What the code implements (6-phase timeline):**
1. Phase 1 (0–500ms): Play icon scales 0.3→1.0 + alpha 0→1 (spring, MediumBouncy)
2. Phase 2 (400–1300ms): 3D flip via scaleX 1→0→1, crossfading play→document
3. Phase 3 (1100–1600ms): "PDF" text fades in on document
4. Phase 4 (1400–1900ms): Violet radial glow expands (alpha 0→0.55, scale 0.3→1.0)
5. Phase 5 (1800–2400ms): "Play2PDF" wordmark slides up + fades in
6. Phase 6 (2400–3200ms): Hold, then navigate

**Issues:**
1. **The flip is fake.** It uses `scaleX` manipulation (1→0→1) to simulate a 3D flip. This looks like a horizontal squish, not a perspective rotation. A real 3D flip would use `graphicsLayer { rotationY = ...; cameraDistance = ... }`.
2. **Phase timing uses sequential `delay()` calls.** These can drift under load. A single `Animatable` with `animateTo` or keyframes would be more precise.
3. **The spring for Phase 1** uses `DampingRatioMediumBouncy` which overshoots. The video (per the code comments) shows a smooth scale-in.
4. **The document icon** draws a play button overlay on the document face. This is a nice touch that communicates the product purpose.
5. **The glow** uses `BrandColors.BrandStrong.copy(alpha = 0.7f)` → `BrandDeep.copy(alpha = 0.4f)` → `Transparent` radial gradient. This matches the violet glow concept.
6. **Wordmark font.** Uses `AppType.display.copy(fontSize = 32.sp)` — Space Grotesk SemiBold at 32sp. The mockup doesn't specify the splash wordmark size explicitly, but 32sp is reasonable for a splash.
7. **Subtitle** says "Playlist → Study guide" with a Unicode arrow. ✓

### 2.5 Shadows & Elevation

The mockups use **no traditional box-shadows on cards at rest**. Depth comes from:
- **Border contrast:** `rgba(255,255,255,0.06)` hairline
- **Background color stepping:** Surface0 → Surface1 → Surface2 → Surface3
- **Top gradient overlay:** `linear-gradient(180deg, rgba(255,255,255,.025), transparent 60%)` on History cards

Shadows appear only on **interaction** and **special elements:**
- Card hover: `box-shadow: 0 16px 34px -16px rgba(var(--glow), .45), 0 4px 14px -8px rgba(0,0,0,.6)` — **colored glow**, not neutral

## 3) Intro Animation Analysis

### 3.1 What the Code Documents

The `SplashScreen.kt` comments describe the MP4 as showing:

> "a glassmorphic play-button icon that rotates/flips and morphs into a PDF document, with 'PDF' text fading in and the wordmark sliding up beneath it."

The implemented 6-phase timeline:

| Phase | Time | What Happens | Easing |
|-------|------|--------------|--------|
| 1 | 0–500ms | Play icon scales 0.3→1.0 + alpha 0→1 | Spring (MediumBouncy, MediumLow stiffness) |
| 2 | 400–1300ms | scaleX 1→0 (play squishes away) then 0→1 (document squishes in) | tween 900ms |
| 3 | 1100–1600ms | "PDF" text fades in on document face | tween 500ms |
| 4 | 1400–1900ms | Violet radial glow expands (alpha 0→0.55, scale 0.3→1.0) | tween 500ms |
| 5 | 1800–2400ms | "Play2PDF" wordmark slides up (offsetY /6→0) + fades in; subtitle appears | tween 500ms + slideInVertically |
| 6 | 2400–3200ms | Hold, then `SplashViewModel.boot()` navigates | — |

### 3.2 Motion Character Assessment

- **Pacing:** 3.2 seconds total. This is **on the longer side** for a splash screen. Most polished apps use 1.5–2.5s. The 800ms hold at the end (Phase 6) feels like dead time.
- **The morph concept is strong.** Play button → PDF document communicates the product's core value proposition ("video becomes document") in a single visual metaphor. This is purposeful, not decorative.
- **The flip implementation is weak.** scaleX manipulation looks like a horizontal squish, not a 3D rotation. There's no perspective foreshortening, no slight rotation, no shadow shift. It reads as "flat animation" rather than "3D transform."
- **The spring overshoot** on Phase 1 (MediumBouncy) may cause the icon to scale past 1.0 and bounce back. If the video shows a smooth ease-out, this is wrong.
- **The glow expansion** (Phase 4) is a nice premium touch. The radial gradient from violet to transparent creates a warm halo.
- **The wordmark slide-up** is standard but effective. The `/6` offset (≈27dp on a 160dp container) is a subtle rise.
- **Overall feel:** The concept is **premium-purposeful** (not playful, not corporate). The execution needs refinement to match the concept's quality.

### 3.3 Implementation Recommendation

**Native Compose Animation is correct. Do not switch to Lottie.**

Reasons:
1. **The animation is procedural Canvas drawing.** Both shapes (play button, document) are drawn with `Path` + `drawRoundRect` + `drawPath`. Lottie would require re-creating these as After Effects layers, then exporting — a lossy round-trip.
2. **The morph is a code-level crossfade.** The `flipProgress` variable drives which shape is drawn. This is trivial in Canvas, awkward in Lottie (would need two layers with opacity/scale keyframes).
3. **The glow is a single `drawCircle` with a radial brush.** Lottie would need a pre-rendered glow frame or a shape layer with blur — heavier and less flexible.
4. **Resolution independence and theming come free** with Canvas. Lottie JSON bakes colors.
5. **The animation is simple enough** — 2 shape draws + 5 animated floats. No particle systems, no bone rigs, no video textures.

**However, the implementation needs these fixes:**
- Replace `scaleX` flip with `graphicsLayer { rotationY = ...; cameraDistance = 8f * density }` for a true 3D perspective flip
- Replace sequential `delay()` with a single `Animatable` keyframe timeline for drift-free sequencing
- Tune the Phase 1 spring to match the video (likely `DampingRatioNoBouncy` or a custom `tween` with `Emphasized` easing)
- Consider reducing total duration from 3200ms to ~2600ms (trim the Phase 6 hold)

**⚠️ I cannot verify any of this against the actual MP4.** I need you to confirm the timeline is accurate or provide a hosted link.
